## Подготовка

Эта инструкция предназначена для оператора, который выполняет процедуру впервые. Прочитайте её целиком до начала работы и выполняйте шаги строго в том порядке, в котором они описаны ниже. Не пропускайте шаги и не меняйте их местами.

Сервис называется «Север». Версия протокола — 2.4. Владелец процедуры — platform-ops. Время указывается в Europe/Moscow.

Перед началом запомните общие правила, которые действуют на всех шагах процедуры:

- Максимальный размер запроса — 8 МиБ.
- Таймаут запроса — 30 секунд.
- Проверка TLS обязательна.
- Секреты нельзя записывать в журнал.

Эти правила не отменяются ни на одном из последующих шагов.

## Проверка входа

Первый рабочий шаг — проверка входного файла. Входной файл имеет формат NDJSON. Пустые строки пропускаются.

Запустите проверку командой:

`northctl validate input.ndjson`

Дождитесь завершения команды и оцените её итог. Сбой проверки означает остановку. В этом случае не переходите к пробному запуску, а действуйте по разделу «Остановка».

Если проверка входа прошла без сбоя, переходите к следующему разделу.

## Пробный запуск

После успешной проверки входа выполните пробный запуск. Режим dry-run не изменяет данные. Пробный запуск выполняется на том же входном файле, который прошёл проверку входа, и предшествует основному выполнению.

Запустите пробный режим командой:

`northctl run --dry-run input.ndjson`

Дождитесь завершения пробного запуска и ознакомьтесь с его выводом. Переходите к выполнению только после того, как пробный запуск завершён.

## Выполнение

Основное выполнение запускается только после проверки входа и пробного запуска. Используйте тот же входной файл, что и на предыдущих шагах.

Запустите выполнение командой:

`northctl run input.ndjson`

Во время выполнения учитывайте правила повторной отправки. Повторная отправка допускается не более 3 раз. Правило для клиентов в исходной формулировке: Clients may retry temporary failures.

Учитывайте также правила дедупликации событий. Ключ дедупликации хранится 24 часа. Первое событие с данным ID сохраняется. Повторный ID не заменяет первое событие.

Правило TLS действует и на этом шаге. Clients must not disable TLS verification.

После завершения выполнения переходите к проверке результата.

## Проверка результата

Последний рабочий шаг — проверка результата выполнения. Запустите её командой:

`northctl verify receipt.json`

Дождитесь завершения команды и оцените её итог. Сбой проверки означает остановку. В этом случае действуйте по разделу «Остановка».

Помните о правилах хранения архива. Архив хранится 14 дней. Удаление архива запрещено.

Если проверка результата прошла без сбоя, процедура завершена. Все шаги выполнены в порядке, описанном в этой инструкции.

## Остановка

Условие остановки взято из карточки фактов. Сбой проверки означает остановку. Это правило применяется на шаге проверки входа и на шаге проверки результата. Также помните, что проверка TLS обязательна: её нельзя отключать, чтобы обойти сбой.

При остановке соблюдайте правила, которые действуют на всех шагах:

- Удаление архива запрещено.
- Секреты нельзя записывать в журнал.
- Clients must not disable TLS verification.

Остановка завершает процедуру. Владелец процедуры — platform-ops.
