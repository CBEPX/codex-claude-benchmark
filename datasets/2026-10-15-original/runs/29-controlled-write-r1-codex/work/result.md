## Подготовка

Сервис называется «Север».
Версия протокола — 2.4.
Владелец процедуры — platform-ops.
Время указывается в Europe/Moscow.
Эти сведения задают контекст процедуры: название сервиса, версию протокола, владельца и часовой пояс. Используйте указанный часовой пояс при указании времени на протяжении процедуры.

Проверка TLS обязательна.
Clients must not disable TLS verification.
Секреты нельзя записывать в журнал.
Сохраняйте проверку TLS при переходе между этапами; запрет на запись секретов в журнал действует в ходе всей процедуры. Подготовка переходит в проверку входа, затем следуют пробный запуск, выполнение и проверка результата. При сбое проверки дальнейший переход прекращается.

## Проверка входа

Входной файл имеет формат NDJSON.
Пустые строки пропускаются.
Максимальный размер запроса — 8 МиБ.
Таймаут запроса — 30 секунд.
Учитывайте различие между форматом входного файла и ограничениями запроса: формат определяет представление входа, а размер и таймаут задают ограничения запроса. Пропуск пустых строк относится к обработке входного файла.

Для проверки входа выполните команду:

```
northctl validate input.ndjson
```

Этот этап посвящён входу. Если проверка завершается сбоем, остановитесь; переход к пробному запуску в таком случае прекращается. После проверки входа переходите к пробному запуску с тем же входным файлом.

## Пробный запуск

Режим dry-run не изменяет данные.
Выполните пробный запуск командой:

```
northctl run --dry-run input.ndjson
```

Пробный запуск следует за проверкой входа и предшествует выполнению. Его свойство — отсутствие изменения данных — относится именно к режиму dry-run. Рассматривайте этот шаг как пробный этап процедуры. Если на этом этапе происходит сбой проверки, остановитесь. Переход к выполнению следует после пробного запуска с учётом общего условия остановки при сбое проверки.

## Выполнение

Для выполнения используйте команду:

```
northctl run input.ndjson
```

Первое событие с данным ID сохраняется.
Повторный ID не заменяет первое событие.
Ключ дедупликации хранится 24 часа.
Эти правила описывают обращение с повторными ID: сохранённое первое событие остаётся первым, а повторный ID не служит его заменой. Указанный срок относится к хранению ключа дедупликации.

Clients may retry temporary failures.
Повторная отправка допускается не более 3 раз.
Разрешение повторять отправку относится к временным сбоям и действует в пределах указанного ограничения. Оно не отменяет остановку при сбое проверки. После выполнения переходите к проверке результата, сохраняя правила TLS и обращения с секретами.

## Проверка результата

Для проверки результата выполните команду:

```
northctl verify receipt.json
```

Эта проверка следует за выполнением и относится к результату процедуры. Не смешивайте её с проверкой входного файла: проверка входа предшествует пробному запуску, а проверка результата идёт после выполнения. Условие остановки распространяется и на этот этап: сбой проверки означает прекращение дальнейших действий по процедуре.

## Остановка

Сбой проверки означает остановку.
Применяйте это условие при проверке входа и проверке результата, а также при сбое проверки на промежуточных этапах. Повторная отправка при временном сбое не отменяет данное условие.

Архив хранится 14 дней.
Удаление архива запрещено.
При остановке сохраняется запрет на удаление архива. Срок хранения архива и срок хранения ключа дедупликации относятся к разным объектам; учитывайте каждый срок для соответствующего объекта. Завершая процедуру после проверки результата, сохраняйте указанные правила хранения и запрет на запись секретов в журнал.
