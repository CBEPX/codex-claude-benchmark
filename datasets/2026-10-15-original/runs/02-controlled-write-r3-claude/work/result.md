# Инструкция оператора: процедура northctl для сервиса «Север»

Инструкция рассчитана на оператора, который выполняет процедуру впервые. Проходите разделы строго по порядку и не переходите к следующему разделу, пока не завершён предыдущий.

## Подготовка

Прежде чем запускать команды, убедитесь, что понимаете, с какой системой и по каким правилам вы работаете.

Сервис называется «Север». Версия протокола — 2.4. Владелец процедуры — platform-ops. Время указывается в Europe/Moscow. Используйте это время во всех отметках, которые делаете по ходу процедуры.

Ознакомьтесь с ограничениями, которые действуют на всех следующих шагах. Максимальный размер запроса — 8 МиБ. Таймаут запроса — 30 секунд.

Отдельно запомните правила безопасности. Проверка TLS обязательна. Clients must not disable TLS verification. Не пытайтесь обойти это правило ни на одном из шагов. Секреты нельзя записывать в журнал. Учитывайте это, когда сохраняете вывод команд или передаёте его коллегам.

Когда эти правила понятны, переходите к проверке входа.

## Проверка входа

На этом шаге вы убеждаетесь, что входной файл пригоден для обработки. Входной файл имеет формат NDJSON. Пустые строки пропускаются. Поэтому их наличие в файле само по себе не является проблемой.

Выполните команду:

```
northctl validate input.ndjson
```

Внимательно прочитайте вывод команды. Если проверка прошла успешно, переходите к пробному запуску. Если проверка завершилась сбоем, дальше не идите и перейдите к разделу «Остановка».

## Пробный запуск

Пробный запуск нужен, чтобы посмотреть на обработку до того, как она затронет данные. Режим dry-run не изменяет данные. Поэтому этот шаг безопасен для выполнения перед основным запуском.

Выполните команду:

```
northctl run --dry-run input.ndjson
```

Изучите вывод команды. Если пробный запуск завершился успешно, переходите к выполнению.

## Выполнение

На этом шаге данные обрабатываются по-настоящему. Перед запуском вспомните, как сервис обращается с повторяющимися событиями. Первое событие с данным ID сохраняется. Повторный ID не заменяет первое событие. Ключ дедупликации хранится 24 часа.

Выполните команду:

```
northctl run input.ndjson
```

Если запрос завершился временным сбоем, его можно отправить снова. Clients may retry temporary failures. Повторная отправка допускается не более 3 раз. Не превышайте это ограничение. Помните, что при любых повторах действуют те же правила безопасности и ограничения из раздела «Подготовка».

После выполнения переходите к проверке результата.

## Проверка результата

На этом шаге вы убеждаетесь, что выполнение дало ожидаемый результат. Выполните команду:

```
northctl verify receipt.json
```

Прочитайте вывод команды. Если проверка прошла успешно, процедура завершена. Если проверка завершилась сбоем, перейдите к разделу «Остановка».

Учитывайте сроки хранения. Архив хранится 14 дней. Помните об этом сроке.

## Остановка

Сбой проверки означает остановку. Это относится и к проверке входа, и к проверке результата: при сбое любой из них не выполняйте следующие команды и не пытайтесь продолжить процедуру в обход проверки.

При остановке соблюдайте те же правила, что и на остальных шагах. Удаление архива запрещено. Это правило действует, даже если результат кажется неверным. Не записывайте секреты в журнал, когда фиксируете причину остановки, и не отключайте проверку TLS, пытаясь устранить проблему.
