# Инструкция по процедуре сервиса «Север»

Инструкция рассчитана на оператора, который выполняет процедуру впервые. Проходите разделы строго по порядку: следующий шаг начинается только после завершения предыдущего. Команды выполняются в том порядке, в котором они приведены ниже.

## Подготовка

Сервис называется «Север». Владелец процедуры — platform-ops. Версия протокола — 2.4. Время указывается в Europe/Moscow.

Входной файл процедуры — `input.ndjson`. Входной файл имеет формат NDJSON. Пустые строки пропускаются.

Учитывайте ограничения запроса. Максимальный размер запроса — 8 МиБ. Таймаут запроса — 30 секунд.

Правила безопасности действуют на всех шагах процедуры. Проверка TLS обязательна. Clients must not disable TLS verification. Секреты нельзя записывать в журнал.

Когда вы ознакомились с этими условиями, переходите к проверке входа.

## Проверка входа

Команда этого шага проверяет входной файл:

```
northctl validate input.ndjson
```

Сбой проверки означает остановку. Если команда завершилась сбоем, не переходите к следующим шагам, а сразу откройте раздел «Остановка». Если проверка входа прошла без сбоя, переходите к пробному запуску.

## Пробный запуск

Команда этого шага выполняет обработку того же входного файла в пробном режиме:

```
northctl run --dry-run input.ndjson
```

Режим dry-run не изменяет данные. Поэтому пробный запуск выполняется до настоящего запуска: он позволяет пройти обработку файла, не затрагивая данные. Убедитесь, что в команде указан флаг `--dry-run`, иначе запуск не будет пробным.

После пробного запуска переходите к выполнению.

## Выполнение

Команда этого шага выполняет настоящую обработку входного файла — уже без флага `--dry-run`:

```
northctl run input.ndjson
```

При обработке действуют правила дедупликации. Первое событие с данным ID сохраняется. Повторный ID не заменяет первое событие. Ключ дедупликации хранится 24 часа.

При временных сбоях допускается повторная отправка. Clients may retry temporary failures. Повторная отправка допускается не более 3 раз. Не превышайте это ограничение.

Помните, что правила из раздела «Подготовка» продолжают действовать: не отключайте проверку TLS и не записывайте секреты в журнал.

После выполнения переходите к проверке результата.

## Проверка результата

Последняя команда процедуры проверяет результат по файлу `receipt.json`:

```
northctl verify receipt.json
```

Здесь действует то же правило, что и при проверке входа: сбой проверки означает остановку. Если команда завершилась сбоем, переходите к разделу «Остановка». Если проверка результата прошла без сбоя, все команды процедуры выполнены в нужном порядке, и процедура завершена.

## Остановка

Процедура останавливается при сбое проверки — как при проверке входа (`northctl validate input.ndjson`), так и при проверке результата (`northctl verify receipt.json`). После остановки не переходите к следующим командам процедуры.

При остановке, как и при штатном завершении, соблюдайте правила хранения архива. Архив хранится 14 дней. Удаление архива запрещено.

Правила безопасности действуют и при остановке: проверку TLS не отключайте, секреты в журнал не записывайте.
