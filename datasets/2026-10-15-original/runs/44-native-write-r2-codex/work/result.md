## Подготовка

Сервис называется «Север».
Версия протокола — 2.4.
Владелец процедуры — platform-ops.
Время указывается в Europe/Moscow.

Процедура начинается с подготовки, затем переходит к проверке входа, пробному запуску, выполнению и проверке результата. Ниже команды приведены последовательно: переходите к следующему этапу после предыдущего, учитывая условия остановки. Если проверка завершается сбоем, дальнейшее выполнение прекращается. Это правило действует при переходах между этапами и при оценке результата.

Проверка TLS обязательна.
Clients must not disable TLS verification.
Секреты нельзя записывать в журнал.

Эти ограничения относятся ко всей процедуре. При подготовке учитывайте их вместе с параметрами запроса и правилами хранения, приведёнными далее. Время в рамках процедуры указывайте в названной зоне. Ответственность за процедуру обозначена владельцем выше.

## Проверка входа

Входной файл имеет формат NDJSON.
Пустые строки пропускаются.
Максимальный размер запроса — 8 МиБ.
Таймаут запроса — 30 секунд.

Начните с проверки входного файла. На этом этапе используется validate; выполнение и пробный запуск следуют далее. Учитывайте формат файла, обработку пустых строк, размер запроса и таймаут как параметры этой процедуры. Для проверки входа выполните:

```text
northctl validate input.ndjson
```

Сбой проверки означает остановку.

После успешной проверки переходите к пробному запуску. При сбое остановитесь на этом этапе: переход к следующей команде противоречит указанному условию. Для дальнейшей обработки событий учитывайте правила сохранения по ID:

Первое событие с данным ID сохраняется.
Повторный ID не заменяет первое событие.

Таким образом, при повторении ID сохраняется первое событие; повторное событие не подменяет его. Эти правила учитывайте и при рассмотрении повторной отправки.

## Пробный запуск

Режим dry-run не изменяет данные.

После проверки входа выполните пробный запуск. Для него предназначена следующая команда; наличие dry-run определяет указанный режим:

```text
northctl run --dry-run input.ndjson
```

Этот этап расположен между проверкой входа и выполнением. Его смысл для оператора — пройти пробный запуск без изменения данных. После него переходите к выполнению, сохраняя общий порядок процедуры. Если возникает сбой проверки, действует условие остановки; пробный режим не отменяет этого условия.

## Выполнение

Для выполнения после пробного запуска используйте run в приведённой ниже форме. Это следующий шаг последовательности, за которым следует проверка результата:

```text
northctl run input.ndjson
```

Clients may retry temporary failures.
Повторная отправка допускается не более 3 раз.
Ключ дедупликации хранится 24 часа.

Разрешение повторять временные сбои учитывайте вместе с пределом повторной отправки и сроком хранения ключа дедупликации. При рассмотрении повторов сохраняются приведённые правила обработки ID. Допустимость повторной отправки не отменяет остановку при сбое проверки.

## Проверка результата

После выполнения переходите к проверке результата. Для этого этапа предназначена verify; выполните следующую команду:

```text
northctl verify receipt.json
```

Оцените исход проверки с учётом общего правила остановки. При её сбое остановитесь. Проверка результата завершает последовательность команд: после неё учитывайте ограничения хранения архива, приведённые в разделе остановки. Успешный переход между предыдущими этапами не отменяет необходимость этого шага.

## Остановка

Архив хранится 14 дней.
Удаление архива запрещено.

При сбое проверки прекращайте дальнейшее выполнение процедуры. Условие остановки учитывается независимо от этапа, на котором выполнялась проверка. При остановке сохраняется запрет удаления архива; срок хранения не служит разрешением на его удаление. Требования к TLS и запрет записи секретов в журнал также сохраняются в рамках процедуры.
