## Подготовка

Сервис называется «Север».
Версия протокола — 2.4.
Владелец процедуры — platform-ops.
Время указывается в Europe/Moscow.

Эта инструкция проводит оператора от проверки входного файла через пробный запуск к выполнению и проверке результата. Соблюдайте последовательность разделов: каждый переход связан с предыдущим шагом, а сбой проверки прекращает процедуру. Название сервиса и версия протокола задают контекст работы; владелец процедуры и часовой пояс относятся ко всей процедуре, а не к отдельному запуску.

Проверка TLS обязательна.
Clients must not disable TLS verification.
Секреты нельзя записывать в журнал.

Соблюдайте эти ограничения при работе с сервисом. Переход к следующему шагу не отменяет обязательность проверки TLS и запрет записи секретов в журнал.

## Проверка входа

Входной файл имеет формат NDJSON.
Пустые строки пропускаются.
Максимальный размер запроса — 8 МиБ.

Начните с проверки входа. Формат файла и ограничение размера запроса относятся к разным объектам: файл представлен в NDJSON, а предел размера установлен для запроса. Пропуск пустых строк — указанное правило обработки входа. Для проверки выполните команду:

```text
northctl validate input.ndjson
```

Сбой проверки означает остановку.

Если проверка завершилась без сбоя, переходите к пробному запуску. При сбое остановитесь: продолжение к пробному запуску и выполнению не соответствует условию остановки. Проверка входа предшествует остальным командам процедуры.

## Пробный запуск

Режим dry-run не изменяет данные.

После проверки входа выполните пробный запуск:

```text
northctl run --dry-run input.ndjson
```

На этом шаге используется режим dry-run. Его свойство — отсутствие изменений данных; это позволяет выполнить пробный шаг перед выполнением. Сохраняйте различие между пробным запуском и следующим шагом: команда здесь содержит параметр dry-run. Правило остановки при сбое проверки остаётся в силе. При отсутствии такого сбоя продолжайте процедуру в указанном порядке.

## Выполнение

Таймаут запроса — 30 секунд.
Повторная отправка допускается не более 3 раз.
Ключ дедупликации хранится 24 часа.
Первое событие с данным ID сохраняется.
Повторный ID не заменяет первое событие.
Clients may retry temporary failures.

После пробного запуска переходите к выполнению:

```text
northctl run input.ndjson
```

При повторной отправке учитывайте установленный предел повторов. Возможность повторить отправку при временном сбое действует вместе с этим ограничением. Правила обработки ID сохраняют первое событие: повторный ID не означает замену уже сохранённого события. Срок хранения ключа дедупликации относится к ключу. После выполнения переходите к проверке результата.

## Проверка результата

Для проверки результата выполните команду:

```text
northctl verify receipt.json
```

Этот шаг следует за выполнением и использует receipt.json. Применяйте к результату проверки то же условие остановки: сбой означает прекращение процедуры. Выполнение команды run предшествует проверке verify; проверка входа validate и пробный запуск dry-run расположены раньше. Таким образом, проверка результата завершает указанную последовательность команд.

## Остановка

Архив хранится 14 дней.
Удаление архива запрещено.

Останавливайте процедуру при сбое проверки независимо от того, на каком шаге проверки он возник. При остановке сохраняется запрет удаления архива. Срок хранения архива и срок хранения ключа дедупликации относятся к разным объектам; не подменяйте одно правило другим. Завершение последовательности команд также не отменяет запрет удаления архива и запрет записи секретов в журнал.
