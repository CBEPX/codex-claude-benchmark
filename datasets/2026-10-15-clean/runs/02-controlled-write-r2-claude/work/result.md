# Инструкция оператора: обработка входного файла сервиса «Север»

Эта инструкция рассчитана на оператора, который выполняет процедуру впервые. Шаги идут строго по порядку: подготовка, проверка входа, пробный запуск, выполнение, проверка результата. Отдельный раздел в конце описывает, когда процедуру нужно остановить. Команды приведены дословно; вводите их в том порядке, в котором они перечислены, не пропуская ни одной.

## Подготовка

Сначала убедитесь, что работаете с нужной системой и понимаете её правила.

Сервис называется «Север». Версия протокола — 2.4. Владелец процедуры — platform-ops. Время указывается в Europe/Moscow.

Перед началом работы учтите требования безопасности, которые действуют на всех последующих шагах без исключения:

- Проверка TLS обязательна.
- Clients must not disable TLS verification.
- Секреты нельзя записывать в журнал.

Это значит, что ни на одном шаге нельзя отключать проверку TLS, а при ведении журнала нужно следить, чтобы в него не попали секреты. Когда вы ознакомились с этими правилами, переходите к проверке входного файла.

## Проверка входа

На этом шаге вы убеждаетесь, что входной файл пригоден для обработки. Входной файл имеет формат NDJSON. Пустые строки пропускаются. Максимальный размер запроса — 8 МиБ.

Выполните проверку входного файла:

```
northctl validate input.ndjson
```

Внимательно посмотрите на итог команды. Сбой проверки означает остановку. Если проверка завершилась сбоем, дальше не идите и перейдите к разделу «Остановка». Если проверка прошла успешно, переходите к пробному запуску.

## Пробный запуск

Пробный запуск позволяет увидеть поведение обработки до настоящего выполнения. Режим dry-run не изменяет данные. Поэтому этот шаг безопасен.

Запустите обработку в пробном режиме:

```
northctl run --dry-run input.ndjson
```

Изучите вывод команды. После пробного запуска переходите к выполнению.

## Выполнение

Теперь запустите настоящую обработку входного файла:

```
northctl run input.ndjson
```

Во время выполнения действуют следующие правила, о которых нужно помнить:

- Таймаут запроса — 30 секунд.
- Clients may retry temporary failures.
- Повторная отправка допускается не более 3 раз.
- Ключ дедупликации хранится 24 часа.

Обратите внимание на то, как обрабатываются события с одинаковым идентификатором. Первое событие с данным ID сохраняется. Повторный ID не заменяет первое событие. Поэтому повторная отправка не приводит к перезаписи уже сохранённого события.

Требования из раздела «Подготовка» продолжают действовать и здесь: не отключайте проверку TLS и не записывайте секреты в журнал. После завершения выполнения переходите к проверке результата.

## Проверка результата

Убедитесь, что выполнение дало корректный результат:

```
northctl verify receipt.json
```

Посмотрите на итог команды. Сбой проверки означает остановку; в этом случае перейдите к разделу «Остановка».

Помните о правилах работы с архивом. Архив хранится 14 дней. Удаление архива запрещено. Не удаляйте архив ни после успешной проверки, ни после сбоя.

## Остановка

Процедура останавливается при сбое любой проверки. Сбой проверки означает остановку. На практике это относится к двум шагам:

- если сбоем завершилась команда `northctl validate input.ndjson` на шаге «Проверка входа», не переходите к пробному запуску и выполнению;
- если сбоем завершилась команда `northctl verify receipt.json` на шаге «Проверка результата», процедура также останавливается.

При остановке продолжают действовать общие правила. Удаление архива запрещено. Секреты нельзя записывать в журнал, в том числе при описании сбоя.
