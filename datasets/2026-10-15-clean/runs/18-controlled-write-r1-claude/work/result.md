# Инструкция оператора: обработка входного файла

Инструкция предназначена для оператора, который выполняет процедуру впервые. Выполняйте разделы строго по порядку и не пропускайте шаги. Все команды приведены дословно и в том порядке, в котором их нужно запускать.

## Подготовка

Перед началом работы уточните контекст процедуры.

Сервис называется «Север». Версия протокола — 2.4. Владелец процедуры — platform-ops. Время указывается в Europe/Moscow.

Соблюдайте требования безопасности на всех шагах. Проверка TLS обязательна. Clients must not disable TLS verification. Секреты нельзя записывать в журнал. Это касается любых заметок и записей, которые вы делаете по ходу процедуры.

Когда контекст понятен, а требования безопасности учтены, переходите к проверке входа.

## Проверка входа

Убедитесь, что входной файл соответствует ожиданиям сервиса. Входной файл имеет формат NDJSON. Пустые строки пропускаются. Максимальный размер запроса — 8 МиБ.

Запустите проверку входного файла:

```
northctl validate input.ndjson
```

Если проверка завершилась сбоем, не переходите дальше, а действуйте по разделу «Остановка». Если сбоя нет, переходите к пробному запуску.

## Пробный запуск

Пробный запуск позволяет увидеть поведение процедуры до реальной обработки. Режим dry-run не изменяет данные. Поэтому этот шаг безопасен.

Выполните пробный запуск:

```
northctl run --dry-run input.ndjson
```

Внимательно изучите вывод команды. При сбое проверки действуйте по разделу «Остановка». Если сбоя нет, переходите к выполнению.

## Выполнение

На этом шаге данные обрабатываются по-настоящему. Запустите обработку:

```
northctl run input.ndjson
```

Учитывайте ограничения сервиса во время выполнения. Таймаут запроса — 30 секунд. Clients may retry temporary failures. Повторная отправка допускается не более 3 раз.

Повторы не приводят к дублированию данных благодаря дедупликации. Ключ дедупликации хранится 24 часа. Первое событие с данным ID сохраняется. Повторный ID не заменяет первое событие. Поэтому, если событие с уже встречавшимся ID придёт повторно, в данных останется первое событие.

Не отключайте проверку TLS даже при повторных попытках. Когда команда завершена, переходите к проверке результата.

## Проверка результата

Убедитесь, что обработка завершилась корректно. Выполните проверку результата:

```
northctl verify receipt.json
```

Если проверка завершилась сбоем, действуйте по разделу «Остановка». Если сбоя нет, процедура считается выполненной.

Помните о правилах работы с архивом. Архив хранится 14 дней. Удаление архива запрещено. Не удаляйте архив ни после успешной проверки, ни после сбоя.

## Остановка

Главное правило остановки сформулировано так. Сбой проверки означает остановку. Это правило действует на каждом шаге, где выполняется проверка: при проверке входа, при пробном запуске и при проверке результата.

При остановке:

- не запускайте следующую команду из списка;
- не отключайте проверку TLS, чтобы обойти сбой;
- не записывайте секреты в журнал, даже если описываете причину сбоя;
- не удаляйте архив;
- если фиксируете время сбоя, указывайте его в Europe/Moscow.

Владелец процедуры — команда platform-ops.
