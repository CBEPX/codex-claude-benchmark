## Подготовка

Сервис называется «Север».
Версия протокола — 2.4.
Владелец процедуры — platform-ops.
Время указывается в Europe/Moscow.

Начните с подготовки к процедуре для указанного сервиса с указанной версией протокола. При работе со временем используйте приведённую временную зону. Сведения о владельце относятся ко всей процедуре: подготовке, проверке входа, пробному запуску, выполнению и проверке результата.

Проверка TLS обязательна.
Секреты нельзя записывать в журнал.
Clients must not disable TLS verification.

Сохраняйте проверку TLS включённой при выполнении процедуры. Запрет на запись секретов относится к журналу; учитывайте его на протяжении работы. После подготовки переходите к входному файлу и его проверке, сохраняя эти ограничения при дальнейших шагах.

## Проверка входа

Входной файл имеет формат NDJSON.
Пустые строки пропускаются.
Максимальный размер запроса — 8 МиБ.

Для проверки входа выполните команду:

```text
northctl validate input.ndjson
```

Здесь проверяется входной файл, с которым связаны последующие пробный запуск и выполнение. При рассмотрении содержимого учитывайте формат входа и правило пропуска пустых строк. Ограничение размера относится к запросу. Не переходите от проверки входа к пробному запуску, если проверка завершилась сбоем: такой результат означает остановку процедуры. После проверки без сбоя переходите к пробному запуску с тем же входным файлом.

## Пробный запуск

Режим dry-run не изменяет данные.

Выполните команду пробного запуска:

```text
northctl run --dry-run input.ndjson
```

Этот шаг предшествует выполнению. Его назначение в последовательности — пробный запуск указанного входного файла в режиме, сохраняющем данные без изменений. Учитывайте это свойство при переходе к выполнению: пробный запуск сам по себе не изменяет данные. Если проверка дала сбой, остановитесь; при отсутствии сбоя проверки продолжайте по порядку к выполнению.

## Выполнение

Таймаут запроса — 30 секунд.
Повторная отправка допускается не более 3 раз.
Ключ дедупликации хранится 24 часа.
Первое событие с данным ID сохраняется.
Повторный ID не заменяет первое событие.
Clients may retry temporary failures.

После пробного запуска выполните команду:

```text
northctl run input.ndjson
```

При временных сбоях учитывайте допустимость повторной отправки и её предел. Разрешение повторять отправку не отменяет указанного ограничения. Для событий с совпадающим ID действует сохранение первого события: повторное событие с тем же ID не заменяет сохранённое. Учитывайте срок хранения ключа дедупликации вместе с этим правилом, не приравнивая повторную отправку к замене первого события. Далее переходите к проверке результата выполнения.

## Проверка результата

Выполните команду проверки результата:

```text
northctl verify receipt.json
```

Архив хранится 14 дней.
Удаление архива запрещено.

Эта проверка следует за выполнением и относится к результату процедуры. При её сбое переходите к остановке. Учитывайте срок хранения архива и запрет удаления совместно: указанный срок хранения не является разрешением оператору удалить архив. Сохраняйте это ограничение и при завершении работы с результатом.

## Остановка

Сбой проверки означает остановку.

Применяйте это правило при проверке входа и проверке результата: сбой проверки прекращает дальнейший переход по процедуре. Допустимость повторной отправки при временных сбоях не отменяет остановку при сбое проверки. При остановке сохраняются обязательность проверки TLS, запрет записи секретов в журнал и запрет удаления архива. Остановка не даёт основания отключать проверку TLS или удалять архив.
